────────────────────────────────────────────────────────────────────────────────
  CONNEXIONS
────────────────────────────────────────────────────────────────────────────────

POST   /connections
  Body : { "receiver_id": 5 }
  => Envoie une demande de connexion à l'utilisateur #5
  Réponse 201 : {
    "success": true,
    "message": "Connection request sent successfully",
    "data": {
      "connection": { "id": 12, "receiver_id": 5, "status": "pending", "created_at": "..." }
    }
  }
  Réponse 400 : { "success": false, "message": "..." }  // si connexion déjà existante

POST   /connections/{id}/accept
  => Accepte la demande de connexion #{id}
  Réponse 200 : {
    "success": true,
    "message": "Connection request accepted",
    "data": {
      "connection": { "id": 12, "sender_id": 3, "receiver_id": 5, "status": "accepted", "updated_at": "..." }
    }
  }

POST   /connections/{id}/reject
  => Refuse la demande de connexion #{id}
  Réponse 200 : même structure que accept avec "status": "rejected"

DELETE /connections/{id}
  => Annule une demande envoyée ou supprime une connexion
  Réponse 200 : { "success": true, "message": "Connection request cancelled" }

GET    /connections?type=all&status=pending
  Params :
    type   : all (défaut) | sent | received | connections
    status : pending | accepted | rejected   (optionnel)

  type=all       => { "data": { "received": [...], "sent": [...] } }
  type=received  => { "data": [...] }   // demandes reçues
  type=sent      => { "data": [...] }   // demandes envoyées
  type=connections => { "data": [...] } // connexions acceptées uniquement

  Chaque élément : {
    "id": 12,
    "user": { "id": 3, "first_name": "Sara", "last_name": "Idrissi", "email": "..." },
    "status": "pending",
    "type": "received",   // sent | received
    "created_at": "...",
    "updated_at": "..."
  }

────────────────────────────────────────────────────────────────────────────────
  CHAMPS VILLES (city_living_id / city_birth_id)
────────────────────────────────────────────────────────────────────────────────

  Les champs city_living et city_birth sont désormais des FK vers la table cities.
  Les IDs sont stables et la liste des villes est disponible via :

  GET /countries  => contient les pays associés aux villes

  Exemples d'IDs courants (selon le seeder) :
    Casablanca => 1
    Rabat      => 2
    Marrakech  => 3
    Paris      => ~42
    Dubaï      => ~72

  La réponse API retourne TOUJOURS les deux :
    "city_living_id": 2,
    "city_living": "Rabat"
